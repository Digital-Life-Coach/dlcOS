# Changelog — dlcOS

| Date | Summary |
|------|---------|
| 2026-08-30 | **v2.1.0 — the live-run fix pass, plus the email add-on.** Every item here came out of one real `/dlcOS:setup` run with an L1, privacy-motivated client on a Linux host. **Broken:** `claude-md-starter.md` advertised `/dlcOS:setup-email` (never existed) and `/dlcOS:setup-dashboard` (real name is `dashboard-setup`) — every scaffolded vault inherited two commands that fail, so a new client's first instinct broke twice out of three. Names fixed, and `setup-email` is now a real skill rather than a deletion. **Broken:** the setup skill and wizard plan pointed at `<plugin-root>/templates/`; templates live at the **marketplace** root and the plugin install cache ships no `templates/` dir at all — same correction the skill already carried for `plans/`, now applied to templates via a `${TEMPLATES}` resolution step. **Contradiction:** Stage 4a step 4 offered "skip the paste" while its own Verify demanded the paste be complete — a client who took the offered choice couldn't pass the stage. Verify now accepts pasted / skipped / merged as three valid resolutions. **New skill — `/dlcOS:setup-email`:** connects Fastmail via Fastmail's hosted MCP server and browser OAuth (no password on disk); reads mail and creates drafts, with no send path anywhere in the add-on. Three other providers documented honestly by capability rather than lumped into "partial": **Google Workspace** is read-only through the desktop connector, but draft-writing *is* reachable via a client-owned Google Cloud project (Gmail API, External+Testing consent screen, `gmail.compose` and pointedly **not** `gmail.send` or full access, desktop OAuth client, local Gmail MCP) — written up as a ~30-45 min coach-driven Tier 2 with its real maintenance cost stated up front (weekly re-auth on External+Testing). **Microsoft 365** reads through the desktop connector and has **no draft-writing path at all**, at any effort level — the skill requires saying that ceiling out loud before the client connects, not after they ask why the Drafts option never appeared. The `dlcOS:email-enabled` marker is written only where draft-writing is both supported and verified end-to-end, so a read-only connector never makes `/dlcOS:draft` offer an option that fails — which is the advertise-what-doesn't-work bug this release exists to stop repeating. Opens by telling the client plainly that read access means messages it reads go to Anthropic, and treats "not now" as a normal answer. **New — `AGENTS.md` template**, written alongside `CLAUDE.md` for every client in Stage 2. `CLAUDE.md` is Claude-only; a client on Codex or Cursor silently lost their vault map and communication preferences. **New — `START-HERE.md` template**, a plain-language client-facing orientation (what the vault is, the 4 memory layers without jargon, where to put things, what's still unfinished, honest cautions). Stage 4b's memory walkthrough was a spoken script, which delivers nothing if the client isn't at the keyboard; this is the durable half. **New — memory-export triage in Stage 4a.** Real exports have contained a named hospice patient's clinical and mental-health detail, a friend's terminal illness, family medical history, and an unresolved death naming a police officer. "Synthesize it" was the wrong default. The wizard now sorts every export into four buckets (client's own durable facts / client's own health / third-party sensitive / practical reference), confirms per category, writes nothing from the third-party bucket without an explicit per-item yes, and never puts health or third-party content into the cloud-stored Settings → Memory block. `chatgpt-memory-export-prompt.md` now leads with the warning that pasting an export into a chat ships all of it to that provider, and recommends the local file path instead. **Rigidity fixed:** the coach-contact CTA ("book time with him at [BLAB link] or text…") was required verbatim, and isn't always true — one client is married to her coach and asks him from the next room. Attribution stays required verbatim; the contact line is now data, set from a new `<!-- dlcOS:coach-contact -->` marker during Stage 2, and must be *true* rather than match a fixed string. **Capability mismatches fixed:** Stage 2 no longer asks L1–L2 clients to choose folder naming (`Action/` vs `Tasks/` vs `Now/`) — that's jargon presented as a preference; they get sensible defaults and a rename offer, L3+ still get the full interview. Stage 6's handoff now branches: L1–L2 get START-HERE.md walked through on screen and three things to remember, not six slash commands, because for them the skills are the *coach's* surface. **Platform:** `dashboard-setup` gains real Linux support — detects the platform first, then writes a launchd plist on macOS or a systemd **user unit** on Linux, with the gotchas that actually bite (`loginctl enable-linger`, no shell expansion in `Environment=`, `bun` off the unit PATH, `journalctl` when `append:` isn't available) and a verify step that makes you log out and back in. Base setup docs gain a Linux prerequisite path; the quickstart no longer claims macOS-only. |
| 2026-07-08 | **v2.0.1 — v2.0.0 install was broken; first validated release.** `/plugin install` rejected v2.0.0 with "invalid manifest": the `agents` manifest field must be an **array of explicit `.md` file paths** — unlike `skills`, it does not accept a directory string (`"./agents/"`). Also fixed two YAML frontmatter parse failures that would have silently dropped all metadata at load: `skills/morning-brief/SKILL.md` and `agents/vault-hygiene.md` both had unquoted `description:` values containing `: ` sequences — now folded block scalars (`>-`). Lesson institutionalized: run `claude plugin validate plugins/dlcOS` before every release; v2.0.0 shipped without it. |
| 2026-06-24 | **v2.0.0 — subagents land + agents that learn.** First release to ship Claude Code **subagents** (the plugin shipped zero before). Four agents, all auto-discovered under scoped names (`dlcOS:<name>`) and generalized to resolve their own vault path via the `dlcOS:vault-root` marker — zero hardcoded paths: **`librarian`** (vault search — humble keyword mode by default, ranked semantic mode when the optional index add-on is installed), **`drafter`** (prose in *your* voice, driven by a fillable `Wiki/Knowledge/voice.md`, with a mechanical avoid-list lint pass), **`webscout`** (primary-source web research), **`vault-hygiene`** (broken-WikiLink detection + safe repair). New skills: `/dlcOS:draft` (spawn drafter + pick delivery), `/dlcOS:vault-lint` (interactive vault repair), `/dlcOS:vault-sweep` (unattended health log), `/dlcOS:promote-lessons` (approve agent-proposed lessons), and the `setup-librarian-index` add-on (provision local semantic search). **Companion-memory loop:** `librarian` and `drafter` read a user-scope `~/.claude/agents/<name>-learned.md` companion at the start of every run and propose ≤3 lessons at the end; `/dlcOS:promote-lessons` approves them — so the agents compound across sessions. Setup wizard gains an optional ≤3-min voice-doc stage (Stage 4c). Versioning note: repo-level SemVer is now the canonical convention (supersedes the early per-skill-SemVer idea from the v1.0 plan — CHANGELOG has been repo-level de-facto since v0.1.0). Docs (README agents section, skills-reference, client-quickstart) updated. |
| 2026-05-22 | **v1.1.0 — memory maintenance + horizon.** New `/dlcOS:monthly-review` — monthly memory + horizon check, cut from the same cloth as `/dlcOS:weekly-review`. Three jobs: synthesize the month's dailies into an L2 `themes-rolling.md` entry; audit L3 memory (`about-me.md` vs. recent reality, Settings → Memory drift, themes hygiene, duplicate facts) with every fix surfaced as an approval draft; then one 90-day horizon question and one cutting-time check-in captured verbatim for next month. Closes the "memory is write-once" gap the wizard's Stage 4b refresh promise depended on. Design lessons folded in from a real `/monthly-review` dogfood run (2026-05-22): forward-look phase added, themes-rolling numbered not bulleted, partial-month/early-run headers supported, richer daily-note wrap with stalled-from-last-month flag and verbatim horizon answers. `claude-md-starter.md` gains a "When You Learn Something Durable About Me" routing block; wizard Stage 4b reworded from quarterly refresh to the monthly `/dlcOS:monthly-review` loop. Docs (skills-reference, client-quickstart, plugin README) updated; `inbox-triage` deferred past v1.1. |
| 2026-05-18 | **v1.0.0 — first public release.** 5 core skills (`setup`, `save-plan`, `resume-plan`, `end`, `weekly-review`, `morning-brief`), guided setup wizard, 13 templates, client-facing docs (quickstart, skills reference, troubleshooting). `end` is now worktree-aware: detects sessions spawned in a git worktree (common when Claude Code launches from the macOS app), commits to the worktree branch, then merges back to `main` and removes the worktree — fixes the "commits never reached main" bug surfaced in pilot testing 2026-05-17. Pending-Plans seeds v1.1 add-ons (`setup-email`, `setup-dashboard`). |
